#+TITLE: Sway on the P25T - a growing tutorial
#+STARTUP: overview

A working guide to sway on the Teclast P25T sway card, written for
someone who has never used sway. It grows with the card: every stage
that adds something adds its section here. The keyboard comes first;
touch is mentioned where it helps.

Conventions: =Super= is the key with the Windows logo (sway calls it
=Mod4=, the config calls it =$mod=). =Super+Shift+q= means: hold Super
and Shift, press q. Commands in =code= are typed literally; words in
=<ANGLE-BRACKETS>= are placeholders.

* What sway is, in five lines
- Sway is a /tiling/ Wayland compositor: it places windows for you,
  without overlaps; you rarely drag anything.
- Everything is reachable from the keyboard; the mouse/touch is optional.
- Windows live in /workspaces/ (numbered 1-10, like virtual desktops).
- On this card every new window opens as a /tab/ filling the screen
  (=workspace_layout tabbed=); the tab titles sit at the top.
- Its behaviour comes from one text file, =~/.config/sway/config=, which
  here is a copy of the repo's =config/sway/config=.

* Starting and stopping
** Before: a keyboard on the tablet
Sway runs from a login on the tablet's own screen (tty1), not over ssh,
so the tablet needs a keyboard:
- the Bluetooth keyboard: it reconnects by itself after a key press, also
  after a reboot (checked 2026-10-16). If it was paired with another
  device in between, pair it with the tablet again: in =bluetoothctl=,
  =remove=, =scan on=, =pair=, then =connect= at once (while the keyboard
  is still in pairing mode), then =trust=;
- or the cable keyboard, with the USB-C port in host mode:
#+begin_src sh
set-usb-role host        # then: sudo reboot
#+end_src
Back to normal (USB cable to the PC) with =set-usb-role normal= and a
reboot. Wi-Fi and ssh work in both modes.

** Start
Sway starts by itself after you log in on tty1 (since 2026-10-16):
- the login prints =sway starts in 3 s - press any key to stay in the
  text console.= Any key in those 3 s gives you the plain tty1 prompt;
- only tty1 does this: tty2-tty6 and ssh logins stay text consoles;
- to turn it off: =touch ~/.no-sway=; on again: =rm ~/.no-sway=;
- sway's messages go to =~/.local/state/sway.log= (the start before:
  =sway.log.old=).
By hand, at a tty1 prompt (after the countdown key, or after leaving
sway):
#+begin_src sh
sway
#+end_src
With the full debug log for a problem report:
#+begin_src sh
sway -d 2> sway.log
#+end_src
The autostart is =~/.config/sway/autostart.sh=, read at login through
the last lines of =~/.profile=.

** Stop
| How                        | What happens                                          |
|----------------------------+-------------------------------------------------------|
| =Super+Shift+e=            | a yellow bar asks; tap/click "Yes, exit sway"          |
| =swaymsg exit= in foot     | leaves at once, no question                           |
| =pkill -x sway= over ssh   | when the screen is stuck                              |
You are back at the tty1 prompt, still logged in: =sway= starts it
again, =exit= logs out (the next tty1 login starts sway again).

** Text consoles while sway runs
=Ctrl+Alt+F2= ... =Ctrl+Alt+F6= switch to text consoles (log in there
as usual); =Ctrl+Alt+F1= goes back to sway.

* Keyboard layout
Spanish first, US second (as on the console).
| Key         | Effect                       |
|-------------+------------------------------|
| =Alt+Shift= | switch es <-> us             |
The bar shows the active layout (=kb es= / =kb us=).

* Windows
| Keys                       | Effect                                              |
|----------------------------+-----------------------------------------------------|
| =Super+Enter=              | new terminal (foot)                                 |
| =Super+d=                  | launcher (fuzzel): type part of a program name, Enter |
| =Super+Shift+q=            | close the focused window                            |
| =Super+Left= / =Right=     | focus previous / next tab (also =Super+h= / =l=)    |
| =Super+Up= / =Down=        | focus up / down (=Super+k= / =j=)                   |
| =Super+Shift+<ARROW>=      | move the window that way                            |
| =Super+f=                  | fullscreen on/off                                   |
| =Super+Shift+space=        | floating on/off (a normal overlapping window)       |
| =Super+space=              | focus between floating and tiled windows            |
| =Super+a=                  | focus the parent container                          |
With a mouse/touch: tap a tab title to focus it; =Super= + drag moves a
floating window.

** Layouts
| Keys      | Layout of the current container                        |
|-----------+--------------------------------------------------------|
| =Super+w= | tabbed (the card's default): one window, tabs on top   |
| =Super+s= | stacking: like tabbed, titles one under the other      |
| =Super+e= | tiled side by side; press again for top/bottom         |
| =Super+b= | next window opens to the right (split horizontal)      |
| =Super+v= | next window opens below (split vertical)               |

** The launcher (fuzzel)
=Super+d= opens a list of the installed programs. Type a few letters,
move with the arrows, =Enter= starts the program, =Escape= closes the
list. Terminal programs (micro, htop, ...) open inside foot.
Settings: =~/.config/fuzzel/fuzzel.ini= (repo =config/fuzzel/fuzzel.ini=):
Terminus 18 px.
foot has three lines in the list: pick plain "Foot". "Foot Server"
starts a background server without a window, and "Foot Client" only
works when that server runs.

** Resizing (tiled windows)
=Super+r= enters resize mode; arrows (or h j k l) grow/shrink by 10 px;
=Enter= or =Escape= leaves it.

** Scratchpad (a hidden drawer)
=Super+Shift+minus= hides the focused window there; =Super+minus= shows
it again (and hides it on the next press). Handy for a terminal you
call up now and then. On the Spanish layout =minus= is the =-= key next
to right Shift.

* Workspaces
| Keys                 | Effect                                         |
|----------------------+------------------------------------------------|
| =Super+1= ... =Super+0= | go to workspace 1 ... 10                    |
| =Super+Shift+1= ...  | move the focused window to workspace 1 ...     |
The bar (top) shows the workspaces in use; tap one to go there.

Settings: =~/.config/foot/foot.ini= (repo =config/foot/foot.ini=):
Terminus 18 px, and the "dim" palette of card 1's console (background
#1c1c1c, text #b0b0b0, toned-down colours, no pure white). To change a
colour, edit the =[colors]= section in the repo file and install it;
new foot windows use it.
| Keys                       | Effect                                   |
|----------------------------+------------------------------------------|
| =Ctrl+Shift+c= / =v=       | copy / paste (clipboard)                 |
| =Shift+Insert=             | paste the last selection                 |
| select with the mouse      | copies to the selection                  |
| =Shift+PageUp= / =PageDown= | scroll back / forward                   |
| =Ctrl+Shift+r=             | search the scrollback                    |
| =Ctrl+plus= / =Ctrl+minus= / =Ctrl+0= | bigger / smaller / reset font (this window only) |
| =Ctrl+Shift+n=             | new foot window in the same folder       |
| =Ctrl+Shift+o=             | pick a URL on screen with the keyboard   |
| =Ctrl+Shift+u=             | type a Unicode character by its code     |

* Programs: PDF, web, pictures
All open as a new tab; start them from =Super+d= (fuzzel) or from foot.
=xdg-open <FILE>= (also Midnight Commander's Enter) picks the program by
file type, from =~/.config/mimeapps.list= (repo =config/mimeapps.list=).
| Program     | Command                        | Opens by default            |
|-------------+--------------------------------+-----------------------------|
| zathura     | =zathura <FILE>.pdf=           | PDF                         |
| Firefox ESR | =firefox-esr <FILE>.html=      | HTML, http/https links      |
| imv         | =imv-wayland <FILE>.png=       | PNG, JPEG, GIF, WebP, BMP, TIFF |
| GNOME Web   | =epiphany-browser <FILE>.html= | - (on trial, lighter than Firefox) |
Note: plain =imv= is a different program (renameutils, renames files).
GNOME Web's window is dark through =ADW_DEBUG_COLOR_SCHEME=prefer-dark=,
set in =~/.config/sway/autostart.sh= (newer GNOME programs ignore the
GTK 3 setting). Web pages without a dark design of their own stay white.

** Firefox
Normal Firefox keys; =Ctrl+o= opens a local file, =Ctrl+q= quits. It is
the heavy program on this tablet: a few seconds to start, 0.5-1 GB with
some tabs. Its frame is dark (=~/.config/gtk-3.0/settings.ini=, repo
=config/gtk-3.0/settings.ini=, asks all GTK programs for dark).

* Screen rotation
Since stage 5, item 1 the screen follows the tablet's position (all four
ways); touch follows by itself.
| Keys      | Effect                                                     |
|-----------+------------------------------------------------------------|
| =Super+o= | lock / unlock the rotation (unlock jumps to the current position) |
Status from foot:
#+begin_src sh
~/.config/sway/autorotate.sh status
#+end_src
By hand (lock first, or the next turn of the tablet overrides it):
=swaymsg output DSI-1 transform <N>= with =<N>= = =90= (landscape, normal), =270= (upside
down), =0= or =180= (portrait).

* The bar
The line at the top right (repo =config/sway/status.sh=, every 2 s):
#+begin_example
kb es | rot lock | bl 32% | vol 70% | wifi <NETWORK> -55dBm | bat 85% chg | Thu 15 Oct 12:00
#+end_example
| Field    | Meaning                                                     |
|----------+-------------------------------------------------------------|
| kb       | keyboard layout, es or us (Alt+Shift)                       |
| rot lock | only while the rotation is locked (=Super+o=)               |
| bl       | backlight, % of maximum                                     |
| vol      | volume of the speaker/headphones mixer ("off" when muted)   |
| wifi     | network name and signal (-40 strong ... -80 weak)           |
| bat      | battery %, then chg (charging), full or plugged             |
To test it over ssh: =bash ~/.config/sway/status.sh once= (=kb ?= there,
because ssh has no sway).

* Brightness, power key and idle
| Keys / event        | Effect                                                      |
|---------------------+-------------------------------------------------------------|
| =Super+F5= / =F6=   | darker / brighter, 5 % steps (also the keyboard's brightness keys) |
| sway start          | backlight 80 (about 32 %), as on the console                |
| power key, short    | screen off / on (sway keeps logind from powering off)        |
| power key, long     | hardware power-off (RK817), as always                       |
| idle 3 min          | dims to the floor (5 %)                                     |
| idle 5 min          | screen off                                                  |
| any key or touch    | undoes the dim / switches the screen on                     |
The brightness never goes below 5 %, so the screen cannot go black by
mistake. By hand, from foot: =~/.config/sway/brightness.sh set 120=
(raw level; =brightness.sh get= prints level and maximum). It works only
from sway, not over ssh. Outside sway (text console) a short press of the
power key still powers the tablet off.

* swaymsg: talking to sway from a terminal
Every config line can also be typed as a command:
#+begin_src sh
swaymsg reload                      # re-read the config (also Super+Shift+c)
swaymsg -t get_outputs              # the screen: mode, transform, scale
swaymsg -t get_inputs               # keyboards, touch, layouts
swaymsg -t get_tree                 # all windows (long JSON)
swaymsg output DSI-1 transform 90   # turn the screen (see rotation)
#+end_src
Over ssh swaymsg needs to be told where sway is (one line, literal):
#+begin_src sh
export SWAYSOCK=/run/user/1000/sway-ipc.1000.$(pgrep -x sway).sock
#+end_src

* Other keys from the default config
| Keys              | Effect                                              |
|-------------------+-----------------------------------------------------|
| =Print=           | screenshot of the whole screen (grim, PNG with the date) |
| =Super+Shift+c=   | reload the config                                   |
The default config also binds the keyboard's volume keys to =pactl=,
which is not installed here: the tablet's own volume buttons work
through triggerhappy (as on the console). Brightness: see "Brightness,
power key and idle".

* Changing the configuration
The files on the tablet are copies of the repo's =config/= folder;
change them in the repo, then install (hp240 tab, then tablet tab):
#+begin_src sh
# hp240
scp -r ~/p25t-backup/p25t-sway/config p25t-sway:p25t-config
scp ~/p25t-backup/p25t-sway/tools/install_user_config.sh p25t-sway:
# tablet (delete p25t-config first if an older copy is there: rm -rf p25t-config)
bash install_user_config.sh p25t-config
#+end_src
The installer needs sway running: it reloads sway to check the config
and puts the old files back if sway reports an error. When sway accepts
it, the installer also adds the autostart lines to =~/.profile= (once;
the old file is kept as =.profile.pre-<DATE>=).

* When something goes wrong
- Sway does not start: look at the end of =~/.local/state/sway.log=,
  or start it by hand with =sway -d 2> sway.log= for the full log (copy
  it to the PC).
- Sway starts and you want the console instead: press a key during the
  3 s countdown, or =touch ~/.no-sway= (over ssh, too).
- The screen is stuck: from ssh, =pkill -x sway=.
- A config error after editing by hand: sway shows a yellow bar with the
  line; fix it and press =Super+Shift+c=, or put the previous file back
  (the installer keeps them as =config.pre-<DATE>=).
- The rotation is wrong: =Super+o= locks it; report with
  =~/.config/sway/autorotate.sh status=.
- The bar shows =[error reading from status command]=: the bar script
  stopped. =Super+Shift+c= (reload) starts it again; report it with the
  output of =bash ~/.config/sway/status.sh once= over ssh.
